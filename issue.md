- [x] 2. Написать `SKILL.md` скилла по спеке.
- [ ] 3. Ревью и merge.

## Требования из интервью (правила кода; применяются только если применимы для языка)
1. Константность: если переменная/метод/аргумент может быть константным — делать константным; не менять ради этого алгоритм/архитектуру, без хаков.
2. Функция >50 строк — разбить на блоки и комбинировать.
3. Тестируемость: классы/методы/функции проектируются под юнит-тесты; тесты без сети, sleep, реальных БД → возможность подмены объектов (DI); время — через аргументы.
4. Инкапсуляция: скрывать реализацию за публичным интерфейсом, минимизировать-shared знания между модулями/хедерами.
5. Явные типы: если переменной можно присвоить явный тип — присвоить; минимизировать нетипизированные переменные.
6. Алиасы для подтипов со смыслом: `using TAddress = std::string; TAddress address = "qwe";`
7. Контракт метода/функции: указывать возможные исключения (в т.ч. транзитивно из вызываемых функций); если исключений быть не должно — noexcept.
