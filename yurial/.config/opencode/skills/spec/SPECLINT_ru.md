# `speclint.py`

Status: stable
Spec source of truth for: `speclint.py` — механическая проверка Markdown-спецификаций, индексов и глоссариев

## Overview

`speclint.py` выполняет детерминированные механические проверки формата спецификаций, структуры prefixed-записей, числовых литералов, индексов и глоссариев. Проверки семантической полноты требований и корректности их смысла остаются за пределами скрипта.

## Scope

**In:** проверка Markdown-файлов и деревьев директорий; распознавание типа файла; проверка prefixed-записей и ссылок; сканирование числовых литералов; проверка `index.md` и `GLOSSARY.md`; выдача диагностик и кодов завершения.

**Out (non-goals):** семантическая оценка однозначности и атомарности требований; доказательство истинности утверждений в `Verification`; оценка семантической достаточности тестовых процедур; проверка качества языка; анализ соответствия исходного кода требованиям.

## Definitions

- `speclint/path` — путь к Markdown-файлу или директории, переданный CLI.
- `prefixed entry` — запись с идентификатором семейства `R`, `E`, `I`, `V`, `T` или `J` в предусмотренной для этого семейства секции.
- `group entry` — запись с дочерними ID; `leaf entry` — запись без дочерних ID.
- `finding` — ошибка, выявленная проверкой и влияющая на итоговый код выхода.
- `warning` — диагностическое предупреждение, не являющееся ошибкой.
- `section` — секция Markdown, определяемая по заголовку вне распознаваемого fenced code block.

## Interface

- `speclint.py <path>...` — проверяет один или несколько путей; каждый путь должен указывать на существующий Markdown-файл или директорию.
- `path` — путь к файлу с расширением `.md` либо к директории, обрабатываемой рекурсивно.
- Коды завершения: `speclint-clean-exit-code` — ошибок и предупреждений нет; `speclint-warning-exit-code` — есть предупреждения, но нет ошибок; `speclint-error-exit-code` — есть ошибки или вызов некорректен.
- Диагностика выводится в `stderr` в формате `<file>:<line>: <message>`; предупреждение начинается с `speclint: warning:`.
- Тип Markdown-файла определяется по базовому имени: `index.md` — индекс, `GLOSSARY.md` — глоссарий, любой другой `.md` — спека.

## Configuration

- `speclint-clean-exit-code`: integer; `0`; fixed; код выхода при отсутствии находок.
- `speclint-warning-exit-code`: integer; `1`; fixed; код выхода при наличии предупреждений и отсутствии ошибок.
- `speclint-error-exit-code`: integer; `2`; fixed; код выхода при ошибках или некорректном вызове.

## Requirements

- R1. CLI и выбор входных файлов:
- R1.1. verification=automated; Скрипт принимает один или несколько позиционных путей к Markdown-файлам или директориям.
- R1.2. verification=automated; Отсутствие аргументов, несуществующий путь или путь к файлу с расширением не `.md` приводит к диагностике в `stderr` и коду `speclint-error-exit-code`.
- R1.3. verification=automated; При получении директории скрипт рекурсивно рассматривает все файлы с расширением `.md` как кандидаты на проверку.
- R1.4. verification=automated; При обработке директории скрипт сначала обрабатывает все `index.md` в сортированном порядке, затем `GLOSSARY.md`, затем остальные `.md` в сортированном порядке.
- R1.5. verification=automated; Тип файла определяется по базовому имени: `index.md` — индекс, `GLOSSARY.md` — глоссарий, остальные Markdown-файлы — спецификации.
- R2. Структура Markdown и секций:
- R2.1. verification=automated; Скрипт распознаёт секции по первому алфавитному слову заголовка Markdown вне распознаваемого fenced code block.
- R2.2. verification=automated; Скрипт проверяет, что семейства записей размещены только в соответствующих секциях: `R` — `Requirements`, `I` — `Implementation`, `E` — `Examples`, `T` — `Tests`, `J` — `Justification`, `V` — `Verification`.
- R2.3. verification=automated; Каждая непустая строка содержимого в секциях `Requirements`, `Examples`, `Implementation`, `Verification`, `Tests` и `Justification` начинается в нулевой колонке с `- ` и ID соответствующего семейства.
- R2.4. verification=automated; Каждая prefixed-запись занимает одну физическую строку, начинается в нулевой колонке с `- ` и непосредственно за маркером содержит ID без вложенности Markdown для выражения иерархии.
- R2.5. verification=automated; Скрипт диагностирует prefixed-запись, начинающуюся с отступа или продолженную следующей строкой с отступом.
- R2.6. verification=automated; Скрипт не рассматривает заголовки внутри распознаваемого fenced code block как переключение секции.
- R3. Идентификаторы и ссылки:
- R3.1. verification=automated; Скрипт проверяет синтаксис и уникальность R-, E-, I-, V-, T- и J-ID в пределах одного файла.
- R3.2. verification=automated; Для многоуровневых ID скрипт проверяет наличие всех предков, корректность групповых и листовых записей и отсутствие групп без дочерних записей.
- R3.3. verification=automated; Скрипт проверяет, что каждый E-ID зеркалирует существующий R-ID.
- R3.4. verification=automated; В секции `Tests` скрипт проверяет ссылки только на существующие листовые R-ID с `verification=automated` или `verification=scenario`.
- R3.5. verification=automated; Скрипт проверяет, что каждая листовая запись R-ID содержит ровно один маркер `verification` со значением `automated`, `scenario`, `manual` или `analysis`.
- R3.6. verification=automated; Скрипт проверяет, что каждый листовой R-ID с `verification=automated` или `verification=scenario` упомянут хотя бы в одной листовой записи T-ID.
- R3.7. verification=automated; Скрипт не требует T-ID для листовых R-ID с `verification=manual` или `verification=analysis`.
- R3.8. verification=automated; Отсутствие обязательной ссылки на T-ID диагностируется как ошибка, а наличие ссылки само по себе не считается доказательством семантической достаточности процедуры.
- R4. Числовые литералы:
- R4.1. verification=automated; Скрипт диагностирует голые числовые литералы вне секций `Configuration` и `Examples`, inline-кода в backticks и распознаваемых fenced code blocks.
- R4.2. verification=automated; Числовой сканер распознаёт целые и десятичные числа, десятичные разделители точкой или запятой и числовые токены с буквенными суффиксами, если токен начинается с числа.
- R4.3. verification=automated; Числовой сканер не принимает цифры внутри идентификаторов, версий, TLS-подобных токенов или токенов, начинающихся с буквы, за голые числовые литералы.
- R4.4. verification=automated; Распознавание fenced code block начинается только по маркеру в нулевой колонке; строки распознанного блока исключаются из числового сканирования.
- R4.5. verification=automated; Закрывающий маркер fenced code block не обязан совпадать с открывающим по символу или длине.
- R4.6. verification=automated; Если fenced code block не закрыт, все последующие строки до конца файла считаются частью блока для числового сканирования и переключения секций.
- R5. Индексы:
- R5.1. verification=automated; Для `index.md` скрипт проверяет наличие полей `Path`, `Reference`, `Status` и `Summary` в каждой записи индекса.
- R5.2. verification=automated; Скрипт принимает для `Status` только `draft` или `stable` и проверяет, что `Reference` состоит из строчных ASCII-букв и цифр, разделённых одиночными дефисами.
- R5.3. verification=automated; Скрипт проверяет существование каждого пути, указанного в индексе.
- R5.4. verification=automated; Путь из индекса разрешается относительно корня git-репозитория, если он определим; иначе путь разрешается относительно родительской директории `specs/` либо директории самого индекса.
- R6. Глоссарий:
- R6.1. verification=automated; Для `GLOSSARY.md` скрипт проверяет форму term ID, использование английского алфавита, алфавитную сортировку и форму поля `Defined in`.
- R6.2. verification=automated; Префиксы term ID разрешаются против Reference ID, собранных из индексов.
- R6.3. verification=automated; Если Reference ID не удалось собрать, скрипт пропускает проверку разрешения префиксов и выводит предупреждение.
- R7. Диагностика и завершение:
- R7.1. verification=automated; Каждая находка выводится в `stderr` в формате `<file>:<line>: <message>`.
- R7.2. verification=automated; Каждое предупреждение имеет префикс `speclint: warning:`.
- R7.3. verification=automated; При отсутствии находок скрипт возвращает `speclint-clean-exit-code`.
- R7.4. verification=automated; При наличии предупреждений и отсутствии ошибок скрипт возвращает `speclint-warning-exit-code`.
- R7.5. verification=automated; При наличии ошибок скрипт возвращает `speclint-error-exit-code`.
- R8. Границы механической проверки:
- R8.1. verification=analysis; Скрипт не заявляет, что механическая проверка устанавливает однозначность, атомарность или смысловую полноту требований.
- R8.2. verification=analysis; Скрипт не заявляет, что проверка подтверждает истинность утверждений в `Verification`, семантическую обоснованность связей или качество языка.
- R8.3. verification=analysis; Ограничения построчного сканера, включая невидимость продолжения без отступа и особенности распознавания fenced code blocks, документируются и учитываются при ревью.

## Implementation

- I1. Реализация выполняется в `speclint.py`. Алгоритм обязан оставаться механическим и воспроизводимым: правила распознавания и их ограничения задаются этой спецификацией; семантический анализ требований и проверка соответствия исходного кода в область ответственности скрипта не входят.
